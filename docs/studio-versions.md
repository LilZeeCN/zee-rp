# 版本、恢复与共享选区

本地开发快照，2026-10-29。版本记录保存在当前工程，包含页面、组件、tokens、变量、数据、字体/素材引用和设计决定。恢复是新的、可撤销的事务，不修改原命名版本。

## 命名版本

编辑器左上角「版本」中填写名字保存；选择「查看差异」，核对涉及页面、图层和字段后再恢复。恢复后可撤销回到后续分支。版本名称不是用户审美批准。

公开工具 `studio_history` 使用同一接口：

```json
{"projectDir":"/abs/project","action":"create","name":"完整学习流程","baseRevision":8,"idempotencyKey":"name-draft-8"}
```

`action:"list"` 列出版本；`action:"preview"` 需 `versionId/baseRevision`，返回差异、目标哈希与 `previewHash`。`action:"restore"` 还需原预览哈希及唯一幂等键。预览后内容变动会拒绝，缺失/损坏快照、较新格式与资源字节漂移明确报错。写入结果未知时先查询当前工程与版本列表，使用原身份核对；不要生成新身份重复恢复。

CLI：`node bin/axure.mjs studio versions --project /abs/project --input /abs/request.json`。高级 `restoreDocument` 是该恢复事务的序列化形式，绑定命名版本、当前内容及预览哈希，通常使用上面的版本工具。

## 历史保留

可撤销历史至多120笔，并按序列化快照8 MiB预算缩小窗口；内存版本缓存也有独立8 MiB预算。一个大于预算的当前快照仍保留。大工程可撤销笔数因此可能少于120，命名版本不会因历史窗口过期被删除。

每120笔或WAL超过8 MiB写检查点，保留当前文档、有效撤销/重做依赖及WAL恢复所需快照，再移除窗口外自动快照。命名版本单独存放。资源目前保守保留，不自动删除图片、原图或字体；恢复时核对清单中的资源。命名版本仍依赖同一工程内的资源字节，独立携带由工程打包工作包继续完善。

1,000节点/500次编辑的本机压力样本中，旧版在512 MiB堆限制下未完成，有限历史加有限场景缓存后完成，Node进程峰值RSS约380 MiB。这是该样本的进程内存证明，不是含浏览器/编译进程的总峰值，也不是任意大工程上限。

## 人与AI共享选择

画布将当前选择连同工程、页面、revision和contentHash发布到本地会话。AI读取：

```json
{"projectDir":"/abs/project","stage":"edit","target":{"selection":"active"}}
```

多个客户端有选择时，明确 `target.clientId`；断开的画布不继续提供活跃选择。空、过期、无法回写或未完整返回的选择不会扩大范围。可写宏参数与实例覆盖仍通过原有作者目标返回。

把 `binding.selectionId` 与 `binding.revision` 交给 `studio_command`。该身份同时检查选择是否已变和源修改是否超出选区；超出范围整批拒绝，即使同批还有合法改动。需要改父容器或全局token时，先明确取得相应更大范围。源变化导致的正常布局影响另见影响报告，不将截图坐标当源坐标。

输入组合、真实浏览器操作、Axure GUI编辑、保存恢复分别记录。本页API说明不能替代这些层级的实际验收。
