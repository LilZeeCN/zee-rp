# 验证流程

先明确本次生成/修改了什么，再按影响选择检查。已有证据与后续待办统一维护在 [能力表](capabilities.md)。历史进展可以关闭相应待办；本次是否执行 GUI/预览检查取决于用户任务与授权，不把某轮推迟验证永久写成禁令。

## 分层证据

| 层级 | 做什么 | 可以证明什么 |
|---|---|---|
| 结构 | `parsePayload` 解析，`encodePayload` 往返，核对修改的字段、引用及目录 | 工具读写自洽；不能证明 Axure 接受 |
| 加载 | 打开副本，确认应用确实打开文件、进程仍在；观察报错并等待异步日志写入 | 这次已加载部分没有发现异常；默认页可能掩盖其他页问题 |
| 切页 | 明确切到每个受影响页面，检查新元件及日志 | 改动页被实际加载；原页面正常不能为另一页背书 |
| 预览行为 | 重新生成预览，实际触发目标交互，观察 Trace、DOM 和可见结果 | 本次目标/参数下的行为有效 |
| GUI 编辑状态 | 对要求继续编辑的面板等进入内部编辑、修改、保存重开 | 编辑器能操作并持久化结构；Web DOM 正常不替代这一项 |

静态复刻还需把预览截图与参考逐区块对照；不要仅凭 widget 数或一张无基线截图报告复刻成功。交互测试选择能归因的动作和目标；例如最终隐藏无法单独证明中间透明度或等待时长正确。

## 预览检查

连接线分别验证“编辑器移动目标 → 保存重开 → 重新生成端点”与“浏览器 Move 移动目标 → 线端”。两种证据不能互相代替；当前 build 的原生双端对照只有编辑器跟随通过。ListBox 默认项往返保留和真实不相邻选择也不等于 GUI 创建多选开关的真值；2026-10-05 已另在 single 对照的新副本中用原生 GUI 开启多选、设置 North/East 并保存关闭重开，再预览实际选择 South/West。自适应原生标签验收需同时观察选中标签与元件覆盖，并在保存关闭重开后复验；Quick win - sample 的基本/V768/V1024/基本及宽度 600/360/480/600 已按此路径通过。

- 点击 Axure 的预览入口重新生成；仅刷新浏览器可能仍是旧页面。
- 跨页测试先检查预览的页面生成范围包含全部目标页。2026-09-24 用户现场反馈：“当前页面”选项曾导致只生成 page_1；`.rp` 有两页和发布产物有两页须分别确认。检查当前 Sitemap 和各页 HTML/data.js，不把 roundtrip 副本、document.js 存在或浏览器刷新当作两页已生成的证明。
- 端口和预览路径会变，按当前应用/浏览器发现，不能沿用旧报告里的 localhost 地址。
- 先确认当前页面和目标元件，再触发交互。Trace 用于确认事件/动作是否触发，DOM 与截图用于确认结果；需要时记录触发前后及中间时间点。
- 条件用例先检查实际样本的 Case、动作和目标。只含 `wait` 的样本不能证明分支产生正确业务效果。
- 中继器动作使用真实中继器和非空数据，不能把图片框当目标后据此判定动作支持。
- 数据动作除了检查行数，还核对列名、唯一业务键和实际值；记录初始行、触发次序以及命中的行。页面生成失败时检查本次路径是否存在页面 data.js，document.js 存在不能代替页面成功。
- 自适应检查绑定和独立覆盖之外，离线验证“添加自适应 → 添加交互”的连续工作流，保留原空 GUID。图片状态按“触发设置动作 → 悬停/移出”检查，状态槽在动作触发后才应用。
- 保存证据时关联文件名、页面/元件、输入参数、预期、实际、日期与 Axure 版本。失败或未执行同样记录，不改写为通过。
- Trace 未开启或未留存时，不能仅凭 Trace 为空推断事件没触发；可用已确认命中的真实点击与 DOM/可见变化判定，并记录 Trace 缺失。
- 同源副本或结构签名相同可以帮助定位，但不把一个条件副本的三分支点击结果扩展成另一个“26 触发器”文件的全部动作通过。
- 本机曾出现第二页跳转陈旧预览路径后 404，诊断与最小绕行见 [故障排查](troubleshooting.md)。它不是所有 Axure 文档的固定规则。

## 旧加载探针

旧探针源码保存在 研究归档（本地研究参考不随发布包），不提供可执行入口。历史版本会 `pkill -x "Axure RP 11"`，然后打开文件并尝试点击窗口中的“否”；这可能丢弃未保存工作。日常验收直接观察应用与日志，不要复制运行该探针。

探针日志路径固定为当天 RP 11 / v4137 的 error_log，默认等 30 秒（`SETTLE` 可调整）。缺当天日志会退出；其他版本需要先确认实际日志路径。它不验证文件打开是否成功、不切页、不检查预览，退出码也不是完整的通过/失败判定。输出零新增异常仅为一条观察。

## 仅整理 Skill 或暂缓应用验证时

- Skill 格式、文档链接、import 路径与 JavaScript/shell 语法。
- `node scripts/axvg.mjs selftest`：组件编码、折线和饼图几何。
- 在副本/内存中针对修改过的行为做回归，再核对源文件未变。
- 自动化系统调用以模拟返回值检查失败报告，不能称为真实剪贴板或 GUI 验证。

这些检查通过后，记录本次离线结果；有新的可追溯应用证据时同步能力表，只有未获得新证据的待办维持原状态。引用历史 GUI/预览结果须注明历史样本，不能称为本次复验。验证被推迟时，交付物标为“已生成，应用/行为待验”，无需为补齐验证反复重建。
